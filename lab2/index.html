⚡ Offline Operations & Synchronisation

How ResQNet operates when network connectivity is unavailable. This is a conceptual explanation — this static HTML/CSS page does not perform real database operations.

1. Local-First Operations

When network connectivity is unavailable, ResQNet continues to operate without interruption. All incident reports, rescue team assignments, resource updates, and shelter occupancy changes are written directly to the browser's local storage layer. Field teams do not experience any operational interruption during network outages.

2. IndexedDB Local Persistence

ResQNet uses the browser's IndexedDB API as its primary data store. IndexedDB is a structured, transactional, client-side database that persists data across browser sessions. It supports indexed queries, making it suitable for emergency operations data such as incident reports, team rosters, and inventory records — all stored locally without any server dependency.

3. Sync Queue & Reconnection

Every data mutation performed offline is recorded in a Pending Synchronisation Queue stored locally. When network connectivity is restored, ResQNet replays these queued operations to the central coordination server in order, applying conflict-resolution rules. No data is lost during the offline period.
